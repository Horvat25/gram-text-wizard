

## Diagnosis: The Pipeline IS Connected End-to-End

After tracing the full flow, here's what I found:

### Current Architecture (working correctly)

```text
Agent (CRON/manual)          VideoRenderingContext (browser)
       │                              │
  1. Decides "video"                  │
  2. Generates script+images          │
  3. Creates post:                    │
     - media_type='reels'             │
     - status='draft'                 │
     - video_url=NULL                 │
     - overlay_metadata.script={...}  │
     - needs_processing=true          │
       │                              │
       └──────── DB ──────────────────┤
                                      │
                                 4. Polls every 30s
                                 5. Finds pending reel
                                 6. Auto-starts render
                                 7. renderFromScript():
                                    - search images
                                    - generate TTS audio
                                    - Canvas + MediaRecorder
                                 8. Upload to Storage
                                 9. Update video_url
                                10. Set status='scheduled'
```

### Console Evidence

The log `[AutoRender] Found 0 pending reels` confirms the worker IS running and polling. It just found zero pending reels at the moment — meaning either:
- The agent hasn't created a video-type post recently
- All existing reels already have `video_url` or exceeded `render_attempts`

### What's Working

- The agent creates reels with the correct `overlay_metadata.script` structure (4 segments with `text` + `imagePrompt`)
- The `VideoRenderingContext` auto-starts when new pending reels appear (via realtime subscription + polling)
- `renderFromScript` takes the agent's pre-generated script and produces a video in-browser
- Completion handler uploads to Storage and sets `status: 'scheduled'`
- Error handling increments `render_attempts` and marks `render_failed` after 3 tries

### One Real Issue Found

The agent's script segments have `imagePrompt` but the images it generates via `search-images-for-video` are stored in `carousel_images` on the post — however `renderFromScript` ignores `carousel_images` and re-searches for images using `imagePrompt`. This means:

**Double image generation**: The agent generates images, then the renderer generates them AGAIN independently.

### Proposed Fix

Modify `VideoRenderingContext.processNextVideo` to pass the post's `carousel_images` (pre-generated by the agent) to `renderFromScript` so images aren't regenerated. This requires:

1. **Fetch `carousel_images` in the pending videos query** — add it to the select
2. **Pass pre-existing image URLs to `renderFromScript`** — modify the segments to include `imageUrl` when available
3. **In `useNarrativeStory.renderFromScript`** — skip image generation for segments that already have an `imageUrl`

This saves ~4 AI image generations per video and speeds up rendering significantly.

### Additional Small Fix

The agent stores `needs_processing: true` in `overlay_metadata`, but the `VideoRenderingContext` doesn't filter on this flag — it picks up ALL draft reels without `video_url`. This is fine (actually better — it catches all cases), but if you want stricter filtering, we could add it.

### Summary

The system works. To verify, trigger the agent manually (or wait for the CRON) with the content distribution set to include videos. When a reel is created, the browser auto-renderer will pick it up within 30 seconds (if the app/PWA is open).

The optimization I recommend is eliminating the duplicate image generation to save costs and speed up rendering.
